bn = totalBlocksCompleted at time of transition (before increment)

─── HYPERTROPHY ─────────────────────────────────────────────────────
  Formula: cycle = (blockNumber + 1) / 2
           cycle % 2 == 1 → .reaccumulation, else → .accumulation

  bn=0  accum         → .deload
  bn=1  deload        → cycle=(1+1)/2=1 → 1%2=1 → .reaccumulation
  bn=2  reaccum       → (_, .reaccum) → .deload
  bn=3  deload        → cycle=(3+1)/2=2 → 2%2=0 → .accumulation
  bn=4  accum         → .deload
  bn=5  deload        → cycle=(5+1)/2=3 → 3%2=1 → .reaccumulation
  bn=6  reaccum       → .deload
  bn=7  deload        → cycle=(7+1)/2=4 → 4%2=0 → .accumulation
  ...
  Training blocks: accum → reaccum → accum → reaccum → accum → ...
  (alternating, with deload between each)

  Block multipliers applied:
    accumulation = 1.0x (base volume)
    reaccumulation = 1.15x (15% more volume — supercompensation phase)

─── STRENGTH ────────────────────────────────────────────────────────
  bn=0  accum         → .deload
  bn=1  deload        → 1<3 → .intensification
  bn=2  intens        → .deload
  bn=3  deload        → 3≥3 → .peak
  bn=4  peak          → default → .accumulation
  bn=5  accum         → .deload
  bn=6  deload        → 6≥3 → .peak
  bn=7  peak          → default → .accumulation
  ...
  Cycle 1: accum → deload → intens → deload → peak
  Cycle 2+: accum → deload → peak (intens skipped after bn≥3)

  KNOWN GAP: After the first 5-block cycle, the `blockNumber < 3`
  condition is permanently false. Strength users in cycle 2+ skip
  intensification and go directly from accumulation to peak. This
  means no intermediate intensity ramp in subsequent cycles. This
  is a deliberate design decision — the initial cycle builds work
  capacity, subsequent cycles assume the athlete can peak directly.
  If this becomes a problem for long-term strength users, change
  `blockNumber < 3` to `blockNumber % 5 < 3` to restore the full
  5-block sequence on every cycle.

  Block multipliers:
    accumulation = 1.0x, intensification = 0.65x, peak = 0.50x

─── POWERBUILDING ───────────────────────────────────────────────────
  bn=0  accum         → .deload
  bn=1  deload        → 1%3==1 → .intensification
  bn=2  intens        → .deload  (NEW: was falling to default→accum)
  bn=3  deload        → 3%3==0 → .reaccumulation  (NOW REACHABLE)
  bn=4  reaccum       → (_, .reaccum) → .deload
  bn=5  deload        → 5%3==2 → .reaccumulation
  bn=6  reaccum       → .deload
  bn=7  deload        → 7%3==1 → .intensification
  bn=8  intens        → .deload
  bn=9  deload        → 9%3==0 → .reaccumulation
  bn=10 reaccum       → .deload
  bn=11 deload        → 11%3==2 → .reaccumulation
  bn=12 reaccum       → .deload
  bn=13 deload        → 13%3==1 → .intensification
  ...
  Training blocks: accum, intens, reaccum, reaccum, intens, reaccum, reaccum, ...
  Pattern: 1 intens per 2 reaccum (repeating)

  Block multipliers:
    accumulation = 1.0x, intensification = 0.65x, reaccumulation = 1.15x

─── RECOMP ──────────────────────────────────────────────────────────
  bn=0  accum         → (.recomp, _) → .deload
  bn=1  deload        → (.recomp, .deload) → .accumulation  (FIX: was looping)
  bn=2  accum         → .deload
  bn=3  deload        → .accumulation
  ...
  Steady state: accumulation ↔ deload
  All blocks use 3+1 week length (recomp override)

║  PART 4 — BLOCK PHASE                                            ║
║  UserProgramInstance.blockPhase (computed property)               ║
╚═══════════════════════════════════════════════════════════════════╝

  blockType        blockWeek   totalBlocksCompleted   → blockPhase
  ───────────────  ──────────  ─────────────────────   ─────────────────────
  .deload          any         any                     .deload
  any non-deload   1           0                       .earlyAccumulation
  any non-deload   1           ≥1                      .postDeloadReintro
  any non-deload   ≤midpoint   any                     .earlyAccumulation
  any non-deload   >midpoint   any                     .lateAccumulation

  midpoint = max(1, blockLength / 2)

  blockLength=5 → midpoint=2: weeks 1-2 early, weeks 3-5 late
  blockLength=4 → midpoint=2: weeks 1-2 early, weeks 3-4 late
  blockLength=3 → midpoint=1: week 1 early, weeks 2-3 late

  NOTE: .intensification phase is NEVER returned by this computed property.
  Even when blockType == .intensification, blockPhase returns
  earlyAccumulation or lateAccumulation.

╔═══════════════════════════════════════════════════════════════════╗
║  PART 15 — SESSIONS PER MUSCLE (frequency divisor)               ║
║  How weekly sets are split across sessions                       ║
╚═══════════════════════════════════════════════════════════════════╝

  This determines setsThisSession = weeklyTarget / sessionsForMuscle.
  sessionsForMuscle = count of day templates containing that muscle.

  ─── 2 DAYS ───────────────────────────────────
  All muscles: 2 sessions → weeklyTarget / 2

  ─── 3 DAYS (PPL) ────────────────────────────
  Chest: 1 (Push only)    → weeklyTarget / 1
  Back:  1 (Pull only)    → weeklyTarget / 1
  Quads: 1 (Legs only)    → weeklyTarget / 1
  (all muscles: 1 session each)

  ─── 3 DAYS (strength full body) ─────────────
  All muscles: 3 sessions → weeklyTarget / 3

  ─── 4 DAYS (ULUL) ──────────────────────────
  Upper muscles: 2 sessions → weeklyTarget / 2
  Lower muscles: 2 sessions → weeklyTarget / 2

  ─── 5 DAYS ──────────────────────────────────
  Push muscles: 1 (PPL) + priority sessions
  Pull muscles: 1 (PPL) + priority sessions
  Leg muscles: 1 (PPL) + priority sessions
  Frequency depends on which muscles are priority.

  ─── 6 DAYS (PPLx2) ─────────────────────────
  Push muscles (Chest,Delts,Triceps): 2 sessions
  Pull muscles (Back,Biceps): 2 sessions
  Leg muscles: 2 sessions (varies by specialization)

  setsThisSession is integer division (rounds down).
  Example: weeklyTarget=11, sessions=2 → 11/2 = 5 per session (1 set lost)

  Session cap: cappedSets = min(setsThisSession, 24 - sessionTotalSets)
  If sessionTotalSets reaches 24, remaining muscles get 0 sets.

║  PART 16 — DURATION BUDGET                                       ║
║  generateBlock() time estimation and filtering                   ║
╚═══════════════════════════════════════════════════════════════════╝

  Formula: estimatedMinutes = (totalSets + slot.sets) × (45 + slot.restSeconds) / 60
  Threshold: sessionDurationTarget + 20 minutes

  If over threshold:
    T3 exercises → ALWAYS skipped
    T2 exercises → skipped if sessionTotalSets > 16
    T1 exercises → NEVER skipped

  Example thresholds:
    target=45  → threshold=65 min   → aggressive trimming
    target=60  → threshold=80 min   → moderate trimming
    target=75  → threshold=95 min   → light trimming
    target=90  → threshold=110 min  → minimal trimming
    target=120 → threshold=140 min  → almost never trims
